## Changes

- `src/components/bulk-selection-toolbar.tsx`: unknown list totals no longer disable server snapshot creation. Calculation clears prior approval/selection and exposes calculating, failed/retry and empty states. The server's returned snapshot count remains authoritative.
- `src/features/annual-return/components/production-whatsapp-automation.tsx`: bulk scope uses distinct, sorted case IDs with a currently displayed row whose `status === "draft"`. Cases represented only by queued, delivered, failed, blocked or unknown rows remain outside bulk selection. Loading/error states expose no bulk toolbar; a read failure no longer appears as an empty follow-up list.
- `src/features/bulk-operations/types.ts` and the annual-return section of `repository.ts`: `draftCaseIds` is a bounded UUID array, passed into the existing `caseScopeSql` `caseIds` predicate alongside current actor/origin filters. An explicit empty array stays empty; it cannot become unrestricted. Other resource kinds reject the restriction. This is a case-level draft-creation scope, not approval to resend messages or regenerate every individual document/payment replacement draft.
- Job detail returns existing persisted operation, assignment target, approving actor ID, creation/progress timestamps and approved payload hash. The UI shows these with resource/count and individual outcome counts. `updated_at` is labelled **last progress update**; there is no dedicated heartbeat field in the existing schema. The approved payload hash includes operation/items and is labelled accordingly, not presented as an independently stored filter/snapshot hash.
- Job result polling is read-only, every five seconds, capped at 60 automatic refresh cycles per cached job query. Only queued/running states poll. Partial/completed/cancelled/unrecognised states and failed reads stop polling; manual refresh remains available. Each result page remains bounded by the existing server limit. If users load additional result pages, a refresh also refreshes those loaded pages. No polling calls resume, retry, reconcile or execute.
- Cancelled jobs disable retry/reconciliation controls. A response containing unknown outcomes cannot display a completed-success label even if its job state says completed. Unknown item counts remain visible.
