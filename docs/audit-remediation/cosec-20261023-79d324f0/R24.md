## Changes

- Configuration, session+actor resolution and root actor reads have a 10-second bound and finish loading on failure. Failed reads produce sanitized unauthenticated, unauthorized or service states. Session/actor failures cannot produce successful password sign-in; inactive or mismatched actors are rejected.
- Transient root failures retain the current URL and use the error boundary retry. A hydrated shell service failure displays retry without redirecting through sign-in. Definitive 401/403 routes retain the safe internal return. Login diagnoses expired callbacks, retries session recovery and releases Google controls after rejection.
- Verified actor changes clear prior query/mutation data before publishing the new session. Sign-out clears local state even when the remote request fails. Request versions prevent pending reads/sign-ins restoring an actor after sign-out. Root provider identity and shell keys discard prior component selection when verified actor/session scope changes.
- Same-actor transient recovery preserves cached records while protected content is hidden until verification succeeds.

## Limits and decisions

- Ruling: root 503 uses an error at the retained route, while provider recovery exposes inline retry; neither is treated as an absent login. This preserves server guard authority and avoids a sign-in loop.
- Ruling: failed remote sign-out removes local actor/cache immediately and keeps denied recovery fail-closed; it does not claim provider-session revocation succeeded.
- Ruling: existing query-scope policy supplies cache cancellation/clearing; root/provider keys additionally clear component state. No separate selection store or auth service/config change.
- Self-review by implementer only; parent final review still required.
- Timeout bounds UI waiting; the existing RPC/client does not expose cancellation, so a network request can complete later. Generation checks prevent late state publication.
- Real magic-link receipt/expiry, invited/inactive accounts, provider 503, sign-out, cross-account HTTP/browser behavior and deployment remain **NOT TESTED**. DB isolation gate is not verified, so no DB action was attempted. Unit fixtures do not close F36/runtime acceptance.
