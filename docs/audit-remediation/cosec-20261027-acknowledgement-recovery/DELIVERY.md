# Escalation acknowledgement uncertain-result reconciliation

Baseline: 2dc7950b820a4a86411dd30754e11b6d7adec991, draft PR #147, codex/cosec-20261023.

The acknowledgement dialog inherited mutation retry defaults and allowed another confirmation after a failed response, even if the acknowledgement had persisted. Closing/reopening could also abandon a pending write's local guard. The mutation now belongs to the keyed actor/queue session, explicitly disables automatic retries and uses a synchronous submission guard. Per-item uncertainty persists across dialog close/reopen and late write errors. Existing queue read-admission and matching active-row rules remain in force.

After uncertainty, an explicit independent listWorkQueuePage read is required. It uses the current filters/cursor, requires a valid page and exactly one matching item with a nonolder integer version and known status/escalation values, cancels older current-page reads before/after the RPC, invalidates other queue caches without refetch and publishes the actual response. Only a successful validated recovery removes that item's write latch. Missing/filtered-out, unavailable, malformed, duplicate or stale-version rows remain closed. Ordinary background success, manual cache changes and query cancellation cannot replace readback.

The mounted dialog retains editable draft text. A fresh acknowledged/closed/inactive-escalation row cannot enable another acknowledgement. A fresh active escalation permits only a new explicit submission after staff compare the displayed state and their draft. A matched row describes current state, not an exact receipt proving who saved which note or that the original command failed. Absence from a filtered page is never inferred to mean success. Changing scope or leaving the keyed queue session rejects late publication. Mounted dialog drafts are not retained after explicit close; the uncertainty/pending-write guards do survive close/reopen within that queue session. No cross-reload persistence is added.

Shared-page race: each recovery replaces a whole queue page. Review identified that independent A/B recoveries could complete in reverse order, letting older A restore B's stale state after B's latch cleared. Latest-recovery generation checks now reject the older response before publication/latch changes. A separate acknowledgement submission epoch rejects readback superseded by a newer acknowledgement write. Per-item read guards deduplicate same-item clicks. Review reported no remaining important findings after the correction.
