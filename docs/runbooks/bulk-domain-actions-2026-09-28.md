# T24 bulk evidence, payment and filing maintenance

## Local implementation and boundaries

The T09 preview, commit, item lease, attempt ledger, cancellation, CSV and resume path now accepts four actions that have actor-scoped single-item services: `reconcilePayments`, `preparePackages`, `recordSubmissions`, and `matchReturns`. Each request supplies unique explicit IDs and an individual payload. The preview is tied to the actor, scope, payload and observed revision for 15 minutes. The runner resolves the saved payload for each item and calls the existing T13–T16 service inside its item transaction. A changed role, team, case permission, revision, proof or provider scan is rechecked by the single-item service. One item error does not approve or mutate another item.

`reconcilePayments` requires each observation's decision and, for a match, its own proof version and confirmed invoice, amount and currency. The single-item reconciliation owns unique allocation and records partial, overpayment, currency and duplicate exceptions. A monthly workbook date is never treated as payment. `preparePackages` produces a draft ZIP and does not approve it. The package service reads verified evidence, checks the manifest and uses a deterministic artifact key; an interrupted database item may leave an unreferenced object with that same key until a later retry or cleanup. `recordSubmissions` records a human external action only with the exact approved package, reference, HKT time and verified submission proof. It never transmits externally. `matchReturns` invokes intake, which stores an exact source identity and either a candidate or an unmatched exception. It never confirms the candidate or closes the case.

`classifyDocuments`, `assignReview`, and `retryAnalysis` remain disabled. There is no existing authorized single-item classification, review assignment, or analysis retry service to reuse. The lower-level analysis queue is not an actor authorization boundary. These actions are absent from the live validator and database action constraint; `evidenceActionAvailability` gives a fixed reason for each. No bulk human document approval is offered.

The T24 `getBulkManualReviewQueue` read endpoint lists the latest 200 unresolved domain items with fixed reason codes and audit IDs; it rechecks the current staff profile and restricts Managers to operations they created in their current team. The existing T09 operation view and CSV expose item state, revision, fixed reason code and audit ID for a human exception queue. The CSV contains no proof bytes, recipient payload, or provider credentials. Preview counts are only a dry run; final single-item checks govern every write. Replaying a committed preview or idempotency key returns the existing operation. Unknown external WhatsApp sends are outside these actions and remain subject to T18/T23 reconciliation rather than automatic retry.
