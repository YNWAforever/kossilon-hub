Source branch is `codex/kossilon-analysis-context`, stacked on T24. Migration `0056_document_analysis_context.sql` records checked provider quotes and run context/model metadata. The forward SQL was applied only to disposable PostgreSQL `kossilon_t20_fresh`; `document-context-analysis-rollback-0056.sql` refuses any nonempty run metadata or evidence before dropping the additions. Production schema and deployment remain unchanged.

The worker inherits the existing verified malware scan gate. It reads a server case/company/party/requirement snapshot and hashes it with the verified document version checksum and rule version. Digital PDF text is extracted first with page text retained for citation validation. With no approved OCR adapter, a scanned, sparse, truncated or unreadable file produces an explicit human review note. The generic byte-only model transport is disabled in the maintenance factory even if a key is configured. No OCR or AI provider was contacted.

The contextual response contract is strict: no approval, send or arbitrary URL fields; only page-quoted observations and claims are accepted. A source version, page, confidence or quote mismatch becomes uncertain. Provider findings stay advisory in `makeFinding`, the database constraints and `blocksRelease`. Run metadata records context hash, rule/model/prompt versions, extraction method, cost and latency when supplied by a future approved provider. The review read compares the current server snapshot with the stored context hash and marks a changed or legacy unbound run `stale`.

Local validation uses anonymous synthetic documents and transaction-cleaned disposable database rows. An approved non-sensitive live sample, real provider contract, storage/scanner runtime and authenticated review browser are still required before runtime verification. T03 production database identity and migration ledger differences must be resolved read-only before a separately authorized production migration.
