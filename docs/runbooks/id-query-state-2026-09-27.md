# T02 ID and query-state regression — 2026-09-27

The shared `entityIdSchema` validates UUID-shaped database keys as 8-4-4-4-12 hexadecimal characters, rejects the nil UUID and malformed/oversized/non-string values, and normalizes valid keys to lowercase. It accepts historical keys such as `40000000-0000-0000-0000-000000000002` as well as standard v4/v7 keys. This is syntax only: server case existence, staff visibility and Client company membership checks remain authoritative. The Client portal now checks company membership again on returned rows in case a repository filter regresses.

The production portal distinguishes no case ID, invalid case ID, loading, failed read, absent/unauthorized case, and loaded case. Demo routing and read-only behavior remain separate. Documents uses the same ID parser, refuses an invalid case link before any all-documents query, and exposes a retry for read errors. Imports now has separate pending/error/empty/success states for batches, companies and review; parties no longer renders 0/0 or “no parties” after a failed read. Error views use generic text and show a bounded server-supplied request ID if available; they never display raw SQL/provider errors or fabricate a correlation ID.
