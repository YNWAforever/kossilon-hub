# Kossilon Hub 職員快速上手

此指引供獲授權的職員在已驗收的環境使用。正式啟用前須核對 [release acceptance](release-acceptance-2026-09-27.md) 的部署、資料庫、供應商及角色證據。Demo 只可閱讀。

## 每日先看

登入後到 `/operations` 查看五分鐘排程。若顯示從未執行、停止、失敗或部分失敗，先記錄排程 run ID、時間與失敗環節，再聯絡當值負責人；人手執行不代表排程已恢復。處理案件時使用案件頁的狀態、待辦及證據提示，不根據畫面空白推斷已完成。

## 一宗案件的次序

1. **月表及 mapping：**上傳月表、核對年度與公司、查看 preview 差異及逐項例外。由有權限職員批准 apply。遇未知公司、衝突或舊 preview，先修正及重新 preview。月表日期只作來源資料，不代表已付款。
2. **追件：**檢查收件人、渠道、內容和版本，先建立 draft，再由獲授權職員批准傳送。不能從未知結果自動重送；先查供應商回條。
3. **文件：**核對公司、案件、類別及版本。掃描未清潔或隔離中的文件不能批准或下載；AI/OCR 提示只供參考，最終由職員覆核。
4. **付款：**核對真實付款證據、金額及所屬案件，由職員作核對決定。未有證據時保留未確認狀態。
5. **交件 package：**檢查 readiness 及 manifest，獨立批准後才下載。下載只代表取得待上載資料，並非已向外部機構交件。
6. **外部提交：**職員在人手外部系統上載，保存提交證明、外部 reference 及時間，再於系統記錄同一 package 的 handoff。系統不會替代人手提交。
7. **回件與結案：**從內部伺服器收件或用 manual intake，核對來源、manifest、reference、文件版本及結果。部分、拒絕或無法匹配的回件須作例外處理。只有已接受並由職員核對的回件，連同其他必需證據齊備，才能結案。

## 角色與批量操作

Admin、Manager、Staff 的權限由伺服器逐項核對；Client 只看獲授權的公司資料。停用帳戶不能讀取、下載或操作。批量操作先 dry-run、查看每項 scope、版本和原因，再批准 commit；失敗項只按操作記錄 resume 或重試，不能繞過單筆的權限與證據檢查。遇權限或版本衝突，保留 audit ID 並交由主管處理。

## 異常

若供應商停機、掃描失敗、排程停止、資料版本變更或提交結果不明，停止相關操作並保留原始紀錄；不要刪除或補寫成成功。記錄案件 ID、操作 ID、時間和錯誤類別，交由負責人按 [pilot operations](pilot-operations.md) 及 [backup and restore](backup-restore.md) 處理。不要在支援訊息貼出金鑰、客戶文件內容或個人資料。
