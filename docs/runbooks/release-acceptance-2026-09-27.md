## T29 review follow-up: legacy completion boundary (2026-09-28)

A RED local integration test showed that a newly created case could be marked Completed with only legacy `filing_reference` and a verified confirmation document, bypassing the approved package, manual submission proof and accepted reconciled return. The production deployment remains the audit commit `3af665418dae4afe14ce91dd194fdfecde10dda4`; this fix is local source and has not been deployed.

Migration `0062_legacy_filing_completion_eligibility.sql` adds `legacy_completion_eligible boolean not null default false`. Its one-time backfill marks only a pre-existing `Filed` case that already has a nonblank filing reference, a verified same-case/company filing confirmation or submission document, and no package. The server requires both this flag and current status `Filed` before accepting that old path. The package path still requires the latest approved revision, recorded human submission with verified proof, and an accepted reconciled return. No browser or bulk action can set the flag.

Read-only production inspection on 2026-09-28 found 21 migration ledger entries through `0020` plus the unknown historical `0006_client_register.sql`; 47 public tables and no `filing_packages` table. One existing `Filed` case meets the verified legacy proof predicate. Current production has one Documents pending case, one Payment pending case and that Filed case. The production deployment is READY at `dpl_3eb48Wud1q6eNjYFh1fwBZ1cUSKT` on the audit SHA. Preview deployment for PR #94 is separate and is not production evidence. The database binding of the deployed app is unverified.

The production preflight, once the existing T01/T03 identity and unknown-ledger reconciliation is complete, is read-only:

```sql
select current_database(), current_schema();
select id from schema_migrations order by id;
select to_regclass('public.filing_packages') as filing_packages;
select
  count(*) filter (where arc.current_status = 'Filed') as filed,
  count(*) filter (
    where arc.current_status = 'Filed'
      and nullif(btrim(arc.filing_reference), '') is not null
      and exists (
        select 1 from documents d
        where d.id = arc.confirmation_document_id
          and d.case_id = arc.id
          and d.company_id = arc.company_id
          and d.verification_status = 'verified'
          and d.file_type in ('filing-confirmation', 'submission')
      )
      and not exists (
        select 1 from filing_packages fp where fp.case_id = arc.id
      )
  ) as eligible_legacy
from annual_return_cases arc;
```

Run the final count only after the preceding migrations create `filing_packages`; before that, omit the `not exists` clause and report the missing table explicitly. Compare case IDs under a restricted reviewer session if the count changes. Do not apply migrations from this read-only inspection. Production schema mutation requires a named snapshot, reviewed SQL, rollback rehearsal, explicit authorization and a maintenance window. The old unknown `0006` ledger entry must be reconciled rather than silently deleted or replayed.
